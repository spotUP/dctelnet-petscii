## Is the canvas drawn correctly? Yes, no vtbuiltin.c fix needed
- Engine: vtengine.c:5694 `v->kitty = im->kind != 0 && im->kind != 4;` so kind 4 gives kitty = 0 (rip_vt.c:96 sets kind 4, kz = -1).
  vt_row_image returns z = image_z = kz = -1 for kind 4 (vtengine.c:5647).
- vtbuiltin.c VtImgRun (~169-210): `if (!v->kitty) { VtImgWrite(whole run) }`; the per-run index-0 skip loop is only for kitty.
  So index 0 is painted. Mutation check: forcing the kitty branch makes the new test fail (index 0 pixel unwritten).
- Under text: VtImgCell (~214) with z < 0 needs VT_CELL_UNDER; VtDrawImages draws under-images, then VtImgUnderText redraws glyphs JAM1.
- Colours: VtImgColours maps pal[1..] via term_pen_map[VtPenFor(RGB|pal[i])].
- Rows redrawn: only the rects VtDraw is called with (engine marks), VtDrawImages(x0,y0,x1,y1).

## Engine gap (not fixed, submodule)
VtImgColours forces vtImgMap[0] = pen of DEFAULT_BG (the vt_image_view contract: "entry 0 = unset pixels, default
background"). A RIP canvas has a real palette entry 0 (RIP palette commands can change it from black), which is
therefore ignored. vt_image_view has no flag telling a RIP canvas from a sixel (both kitty = 0). Fix needs an engine
field (e.g. view.opaque0 / kind) so the renderer uses pal[0] for kind 4; then VtImgColours keys on that field.
Also: rip_settle copies cv->pal into im->pal every change, so a changed pal[0] would reach the view.

## Dirty tracking: one reader
DCTelnet never reads canvas state (grep: no cv_*, vt_rip_* use in src/*.c outside third_party). The only
cv_take_dirty is the engine's rip_settle (rip_vt.c:234): cv_flush, discard dirty rect, bump im->serial,
image_mark(slot) which mark()s the cells of every placement. The renderer learns through the normal VtDraw rect
callbacks for those cells, and vtImgSerial (vtbuiltin.c VtImgColours) rebuilds the pen map when serial moves.
Consequence: whole-canvas cells are marked on every change (no sub-rect granularity); the 68000 cost is per marked cell run.

## Not yet wired in DCTelnet
vt_set_rip is not called anywhere in src/ (test calls it directly). The VtDraw route for a resized terminal
smaller than 44 rows draws only the visible part (test grid 80x30 cells of 8x8 = 240 px of 350).
